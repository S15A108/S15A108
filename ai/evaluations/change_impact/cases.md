# 변경 영향 분석 평가 사례

모든 사례는 독립적인 가상 프로젝트의 승인 전 변경 제안이다. 아래 `source`는 관련 승인 설계의 문서 ID·문서 버전·위치를 사람이 읽기 쉽게 표시한다. 제안된 본문은 승인된 근거로 취급하지 않는다.

## C01. 명시 관계로 찾은 영향 후보

| 입력 | 내용 |
| --- | --- |
| 변경 제안 | 정책 `301`의 승인 버전 `311`: “회원 조회는 로그인한 사용자만 가능” → 제안: “회원 조회는 관리자만 가능” |
| 승인 설계 | 정책 `301`/`311`, 출처 문서 `201`/버전 `211`, `인증 정책 / 회원 조회 권한`. API `302`/`312`: `GET /members/{memberId}`, 출처 문서 `202`/버전 `212`, `회원 API / 회원 조회` |
| 명시 관계 | API `302`가 정책 `301`에 의존한다는 확인된 관계 |
| 열린 작업 | 작업 `501`, 담당 멤버 `21`: 일반 로그인 사용자가 회원 상세를 조회하는 화면 구현. 현재 계획이 API `302`/`312`를 참조 |

**사람의 기대:** 규칙이 `정책 ← API ← 작업 501` 경로를 찾는 경우 경로를 규칙 근거로 따로 보존한다. AI는 변경 전후 권한과 작업의 일반 사용자 조회 범위가 다르다는 **검토 후보**를 설명할 수 있다. 정책의 문서·버전과 작업 계획에 실제 들어 있는 내용이 뒷받침해야 한다. 후보만으로 작업을 수정하거나 관계를 승인하지 않는다.

**범위 확인:** 규칙 후보·경로를 AI 요청으로 전달하는 방식은 현재 계약에서 확정되지 않았다. 규칙 실행 자체를 AI의 성능으로 채점하지 않는다.

## C02. 명시 연결이 없어도 의미상 관련될 수 있는 후보

| 입력 | 내용 |
| --- | --- |
| 변경 제안 | API `303`의 승인 버전 `313`: 로그인 성공 응답 필드 `userId` → 제안: `memberId` |
| 승인 설계 | API `303`/`313`, 출처 문서 `203`/버전 `213`, `로그인 API / 응답` |
| 명시 관계 | API `303`과 작업 `502` 사이의 확정 참조는 전달되지 않음 |
| 열린 작업 | 작업 `502`, 담당 멤버 `22`: “로그인 응답의 `userId`를 읽어 사용자 프로필을 표시한다.” 현재 계획은 API `303`을 명시 참조하지 않음 |

**사람의 기대:** 전달된 작업 설명과 변경 내용이 실제로 같은 로그인 응답을 가리킨다는 점에 근거해, 작업 `502`가 영향을 받을 **가능성**을 제시할 수 있다. 명시 관계가 존재한다고 꾸며내거나 확정 충돌로 표현하면 안 된다. API 문서의 출처와 작업 계획의 내용을 구분해 확인한다.

**범위 확인:** 규칙 밖의 추가 후보를 #188 MVP에서 탐색할지는 합의되지 않았다. 이 사례는 탐색 기능을 이미 확정한 요구사항이나 자동 통과 기준이 아니다.

## C03. 근거가 부족한 작업

| 입력 | 내용 |
| --- | --- |
| 변경 제안 | API `304`의 승인 버전 `314`: 회원 응답에 `email`이 포함됨 → 제안: `email` 제거 |
| 승인 설계 | API `304`/`314`, 출처 문서 `204`/버전 `214`, `회원 API / 응답` |
| 명시 관계 | 관련 확정 관계 없음 |
| 열린 작업 | 작업 `503`, 담당 멤버 `23`: “회원 화면을 만든다.” 사용할 응답 필드는 기록되지 않음 |

**사람의 기대:** 작업 `503`이 `email`을 사용한다고 단정하거나 “영향 없음”을 확정하지 않는다. 추가 작업 계획이나 사용처를 확인해야 한다는 것이 사람이 평가할 기대 사항이다. 현행 AI-A03에는 정보 부족을 나타내는 별도 필드가 없으므로 실제 표현 방법은 계약 협의 후 정한다.

## C04. 입력 범위에서 확인된 영향 후보 없음

| 입력 | 내용 |
| --- | --- |
| 변경 제안 | API `305`의 승인 버전 `315`: `GET /members` 응답의 설명 문구만 변경. 경로·필드·권한은 그대로라고 제안에 명시 |
| 승인 설계 | API `305`/`315`, 출처 문서 `205`/버전 `215`, `회원 API / 목록` |
| 명시 관계 | 관련 확정 관계 없음 |
| 열린 작업 | 작업 `504`, 담당 멤버 `24`: API 응답의 `memberId`를 사용해 목록을 표시 |

**사람의 기대:** 입력에 없는 동작 변경이나 영향 후보를 만들어내지 않는다. 분석이 정상적으로 완료되고 제공된 범위에서 추가 후보가 없다면 빈 `candidates`가 가능하다. 이는 프로젝트 전체에 영향이 없다는 보장이 아니며, 검색·모델 호출 실패를 빈 성공 결과로 표현해서도 안 된다.
