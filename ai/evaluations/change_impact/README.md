# 변경 영향 분석 평가 사례 초안 (#188)

`cases.md`는 AI-A03 변경 영향 분석의 **사람이 작성한 가상 평가 사례**다. 실제 프로젝트 데이터나 모델 실행 결과가 아니다. 계약과 역할이 합의된 뒤 입력을 API 요청으로 만들고, 결과를 이 기대 사항과 비교한다. 현재 파일은 자동 실행 fixture나 확정 API 스키마가 아니다.

## 기준과 구분

- 현행 [AI-A03 계약 초안](../../../docs/api/03-ai-internal.md#ai-a03)의 입력은 변경 제안 `changes`, 관련 승인 설계 `approved_items`, 명시 관계 `explicit_dependencies`, 열린 작업 `open_tasks`다. 사례의 표는 이 입력을 사람이 읽기 쉽게 요약한 것이며 필수 필드를 모두 나열하지 않는다.
- 비교 대상은 **승인된 기존 설계와 변경 제안**이다. 제안 내용은 아직 승인되지 않았고, 가상의 `v2` 확정본으로 취급하지 않는다.
- 규칙으로 발견한 경로는 AI 해석과 분리한다. 현행 AI-A03 요청에 규칙 후보·경로 필드는 없다. 해당 입력 추가 여부와 AI의 독립 후보 탐색 범위는 합의 후 확정한다.
- AI 결과는 검토할 후보이며, 관계 확정·승인·작업 상태 변경을 뜻하지 않는다. 근거가 부족할 때 영향 없다고 단정하거나, 제공되지 않은 출처·담당자·내용을 만들어내지 않는다.
- 현행 `ImpactResult`는 `candidates`만 정의한다. 정보 부족을 별도 상태로 어떻게 표현할지는 미결이므로, 이 사례는 새로운 응답 상태나 필드의 확정을 전제하지 않는다. 실패와 빈 성공을 혼동하지 않는다.

## 평가 방법

1. 사례의 기존 설계·제안·관계·작업을 읽고 계약에 맞는 요청을 준비한다. 같은 ID의 버전과 출처는 입력에 명시한다.
2. 결과에서 찾은 후보와 이유를 사람이 확인한다. 작업·담당자·설계 ID 및 출처는 입력과 대조한다.
3. `cases.md`의 기대 사항과 비교하고, 잘못된 후보·누락·근거 없는 주장·불확실성 표현을 별도로 기록한다. 독립 후보 탐색이 MVP에 포함되는지는 합의 후 해당 사례의 평가 기준을 결정한다.
4. 실행했다면 모델·프롬프트 버전·실행 시각과 실제 결과를 별도로 남긴다. 아직 실행하지 않았으므로 정확도나 통과 여부는 기록하지 않는다.

평가 시 응답·프롬프트에 포함된 프로젝트 자료를 임의로 외부에 공개하지 않는다. 이 사례는 식별값과 내용이 모두 가상이다.

## 실행 도구

`ai/`에서 아래 명령은 구조화된 가상 사례 네 건을 검증하며 모델을 호출하지 않는다.

```bash
python -m evaluations.change_impact.run
```

실제 모델로 평가하려면 `AI_IMPACT_EVAL_ENDPOINT`(Chat Completions URL), `AI_IMPACT_EVAL_API_KEY`, `AI_IMPACT_EVAL_MODEL`을 실행 환경에 설정하고 다음을 명시적으로 실행한다. 호출 비용이 발생할 수 있다.

```bash
python -m evaluations.change_impact.run --execute --output impact-evaluation.json
```

구조화 출력 지원 모델은 `--response-format json_schema`를 추가해 비교할 수 있다. 기본값은 `json_object`이며, 스키마를 지원하지 않는 공급자에서 자동으로 다른 방식으로 재호출하지 않는다.

출력에는 후보·사용량·실패가 기록된다. 대상 ID 일치는 참고 지표일 뿐이다. 근거 부족 사례와 AI의 설명·인용 정확성은 사람이 확인해야 하며 결과가 자동으로 정답이나 승인 판정이 되지 않는다.

첫 실제 모델 평가의 사례별 결과와 한계는 [2026-10-28 평가 기록](results-2026-10-28.md)을 참고한다. 이후 [구조화 출력 평가](results-2026-10-28-structured.md)와 [보완 후 재평가](results-2026-10-28-postfix.md)도 남겼다.
