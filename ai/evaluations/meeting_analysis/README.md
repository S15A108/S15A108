# 회의 분석 예시 점검 (#190)

`run.py`는 실제 GMS 호출을 수행한다. 호출 비용이 발생하며, 코드에 들어 있는 **가상의 회의 기록만** 전송한다. 실행 전에 해당 모델과 키를 사용할 권한이 필요하다.

```powershell
python -m evaluations.meeting_analysis.run --env-file <설정파일경로> --mode MINUTES
python -m evaluations.meeting_analysis.run --env-file <설정파일경로> --mode QUESTIONS
```

## 2026-11-02 수동 확인

- 입력: 회원 조회 응답의 `memberId` 유지에 참가자가 동의하고, 오류 재시도 정책은 미결정이라고 명시한 가상 회의.
- `MINUTES`: GMS `gpt-6-luna` 호출 성공. `memberId` 유지는 결정, 재시도 정책은 미결 항목으로 구분하고 참가자 동의를 결정 근거로 설명했다. 사용량은 입력 614 / 출력 178 토큰으로 반환됐다.
- `QUESTIONS`: 같은 모델로 호출 성공. 재시도 조건·횟수·간격 확인을 제안했으나, 참가자의 동의가 있는 `memberId` 유지에 대해서도 확정 여부를 확인하자는 질문을 제시했다. 과도한 재확인 가능성이 있어 추가 사례 평가가 필요하다. 입력 581 / 출력 278 토큰. 이 실행 뒤 회의록 모드의 결정 근거 설명을 위한 공통 프롬프트 문장 한 줄을 추가했다.
- 두 호출 모두 `MEETING_ANALYSIS` usage가 반환됐다. 위 토큰 수는 이 실행의 값이며 매번 달라질 수 있다.

이 확인은 각각 하나의 짧은 예시에 대한 기본 동작 점검이다. 결과의 사실성이나 출처의 의미적 타당성을 보장하지 않으며, BE 연동과 회의록별 결정 근거의 구조화 계약은 별도 검토가 필요하다.
