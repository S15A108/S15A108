# 작업계획 검증 AI 실모델 평가 (2026-10-29)

## 실행 범위

실제 OpenAI API를 호출했다. FastAPI `/v1/validate` 라우터는 ASGI 테스트 전송과 테스트 전용 OpenAI provider 주입으로 실행했다. 합성 입력만 사용했다. BE·PostgreSQL·운영 GMS 설정 및 네트워크 HTTP 서버는 이 평가의 대상이 아니다. JSON의 원문 응답과 사용량도 합성 데이터이다.

## 최종 비교 실행

모델: `gpt-4.1-2025-04-14`, 응답 형식: strict `json_schema`. 4건 단일 실행이며, 신뢰도나 일반화된 정확도를 뜻하지 않는다. [OpenAI 모델 문서](https://developers.openai.com/api/docs/models/gpt-4.1)는 해당 모델을 deprecated로 표시하므로 실제 운영 모델 선정의 근거로 삼지 않는다.

| 사례 | 관측 | 기대 대조 |
| --- | --- | --- |
| 정상 | HTTP 200, COMPLETE, finding 없음 | 통과 |
| userId/memberId 불일치 | HTTP 200, COMPLETE, MISMATCH/BLOCKING, 버전 311 인용 | 통과 |
| 정책 미확정 | HTTP 200, PARTIAL/EVIDENCE_INSUFFICIENT | 통과. 최종 PASS가 아니다. |
| 원문과 승인 내용 충돌 | HTTP 200, COMPLETE, MISMATCH/BLOCKING, 버전과 원문 evidence 인용 | 통과 |

최종 4건: 입력 7,284 토큰, 출력 567 토큰. 비용은 실제 청구서로 확인해야 하며 usage에 비용이 없으면 계산하여 확정하지 않는다. 자세한 원문·개별 usage는 `results-live-gpt41-final.json`이다.

## 시행 과정과 한계

- `gpt-4o-mini-2024-07-18`의 기존 JSON 출력은 0/4, strict schema도 0/4였다. 일부는 검사 키·출처 계약 위반, 일부는 근거 부족으로 분류했다.
- GPT-4.1 strict의 첫 시행은 1/4였다. 모델이 현재 작업을 관련 작업으로 인용하거나 검사 키와 근거를 잘못 연결했다.
- 계약 설명을 보완한 시행은 2/4였다. 불일치를 CONFLICT로 분류하고 정상 계획에 불필요한 finding을 생성했다. 마지막 분류 지침 보완 뒤 4/4가 나왔다. 중간 결과도 `results-live*.json`에 보존한다. 이 네 사례를 바탕으로 지침을 수정했으므로 최종 결과는 독립 holdout 평가가 아니다.

- 이 AI 단독 평가 이후 BE가 승인 원문 행 범위와 해시를 검증해 evidence를 전달하도록 수정했다. 로컬 테스트 AI provider 선택과 BE 사용량 provider 설정도 명시적으로 맞췄다. 운영 구성에서는 두 설정의 일치를 확인해야 한다.
