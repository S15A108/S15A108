# 작업계획 의미 분석 초기 구현 (#184)

`POST /v1/validate`는 BE가 전달한 작업계획 리비전, 승인 설계, 관련 작업,
검사 범위, 출처와 원문 발췌를 공통 LLM 클라이언트에 전달한다. AI는 DB나
원문 저장소를 재조회하지 않고 최종 PASS를 결정하지 않는다. 의미 분석 결과와
실제 호출별 usage를 반환하며, 검사 불가 항목은 `PARTIAL`로 반환한다.

입력 검사에서 미지원 kind/schema, 중복 check, 참조되지 않은 버전, 근거의
문서 버전 불일치, 잘못된 행 범위, 입력 크기와 시간 예산을 확인한다.
출력 검사에서 각 check가 완료 또는 미검사로 정확히 한 번 분류되었는지,
finding의 ID와 출처가 입력 및 해당 check에 속하는지 확인한다. 형식·ID
검증은 모델 설명이 사실임을 보증하지 않는다.

`MISMATCH`/`CONFLICT`에는 해당 check의 설계 버전 또는 관련 작업을 식별하는
참조가 필요하다. 수동 입력한 승인 설계나 관련 작업 계획은 원문 출처 없이도
비교 대상이 될 수 있다. `unresolved`가 비어 있지 않은데 모델이 모든 검사를
완료했다고 반환하면 결과를 거부한다. 이 보수적 검사는 어느 미확정 사항이
어느 check에 속하는지를 증명하지 못한다.

호출 예산은 요청당 최대 60초, 입력 JSON은 UTF-8 기준 최대 200,000바이트다.
이는 초기 구현 제한이며 운영 합의값은 아니다. 검증 모델 호출은 한 번이며
자동 재시도하지 않는다. timeout/공급자/출력 검증 실패에서는 실제 호출
usage를 오류 응답에 보존한다. 기본 형식은 `json_object`이며, 공급자와 모델이
엄격한 JSON Schema 출력을 지원할 때만 `VALIDATION_RESPONSE_FORMAT=json_schema`를
선택할 수 있다. 형식을 바꿔도 검사 범위·출처·ID의 별도 검증은 그대로이며,
모델이 생성한 의미적 판단의 정확성이 보장되는 것은 아니다. 공급자에서 해당
형식을 지원하지 않으면 자동 폴백이나 재호출 없이 실패한다.

## 아직 연결되지 않은 부분

- BE 워커에서 검색·check 선정·판정·결과 저장 경로를 연결했다. 문서 청크의
  검증된 원문 발췌 전달은 명시적 행 범위가 있는 경우 구현됐고 작업계획
  벡터 검색은 아직 구현되지 않았다. 필수
  서버 규칙과 요청 범위를 검증한 제한적 MVP에서만 PASS/NEEDS_INPUT을
  확정한다. 미확정 범위는 HUMAN_REVIEW로 보류한다. 상세는
  `docs/design/plan-validation-184-inventory.md` 참고.
- 설계 content의 검사별 충분성, 검증 범위와 정책 부재 증명 형식은 Q01/Q02
  확정이 필요하다. 증거 없는 정책 부재를 단정하지 않도록 모델에 PARTIAL을
  요청하며, MISSING_POLICY 모델 출력은 현재 오류로 거부한다. unresolved
  문자열이나 원문 속 미정 표현만으로 특정 정책의 미확정 상태를 기계적으로
  검증할 수 없으므로 명시된 미정 사례도 아직 지원하지 않는다.
- 현재 호출은 GMS Chat Completions URL과 `BEE_DEFAULT_MODEL`을 사용한다.
  공급자·모델의 해당 경로 호환성은 실호출로 검증되지 않았으며, 검증 전용
  모델 설정과 운영 시간 예산은 합의가 필요하다.
- LLM의 근거 부족 판단이나 의미 분석 정확도는 스키마 검사만으로 보장할 수
  없다. 특히 API content에 method/path만 있는 경우도 유효하지만 특정 검사를
  위한 상세 필드가 빠졌을 수 있다. 프롬프트에서 이를 미검사로 분류하게
  요청하더라도 모델의 답을 확실하게 검증할 수 없어, 별도의 실제 모델 평가와
  사람 검토가 필요하다.

## 검증

`ai/`에서 `python -m pytest tests/test_validation.py -q`를 실행한다.
이 테스트는 합성 공급자를 사용하고 실모델 정확도를 측정하지 않는다.
